Git이란?

Git은 2005년 리눅스 커널 개발을 위해 탄생한 오픈 소스 버전 관리 도구입니다. 프로젝트 폴더 안의 .git 디렉터리에 커밋(스냅샷) 기록이 저장되며, 각 개발자 PC에 전체 이력이 복제될 수 있어 분산형이라고 부릅니다.

저장소(Repository)

프로젝트와 그 변경 이력이 담긴 공간입니다. 로컬 또는 GitHub 같은 원격에 둘 수 있습니다.

커밋(Commit)

특정 시점의 파일 상태를 메시지와 함께 저장한 기록 단위입니다.

브랜치(Branch)

기능 개발·버그 수정 등을 본선과 분리해 진행할 수 있는 독립된 작업선입니다.

왜 Git을 쓰나요?

  • 언제, 무엇이, 왜 바뀌었는지 추적할 수 있습니다.
  • 실험용 브랜치로 안전하게 시도한 뒤 병합할 수 있습니다.
  • 충돌을 비교·해결하며 여러 명이 동시에 작업할 수 있습니다.
  • 오프라인에서도 커밋·브랜치 작업이 가능합니다.

GitHub, GitLab, Bitbucket 등은 Git 저장소를 호스팅하는 서비스이며, Git 자체와는 별개입니다. Git을 익히면 어떤 호스팅에도 같은 방식으로 사용할 수 있습니다.

설치 방법

공식 배포판은 git-scm.com에서 확인할 수 있습니다.

  1. Git for Windows 설치 프로그램을 받습니다.
  2. 설치 마법사에서 기본 옵션을 유지해도 대부분의 경우 충분합니다.
  3. 설치 후 Git Bash 또는 PowerShell·명령 프롬프트를 엽니다.

또는 winget으로 설치할 수 있습니다.

winget install --id Git.Git -e --source winget

Xcode Command Line Tools에 Git이 포함되거나, Homebrew로 최신 버전을 설치합니다.

# Homebrew가 있다면
brew install git

공식 인스톨러: macOS용 Git

배포판 패키지 관리자를 사용합니다.

# Debian / Ubuntu
sudo apt update && sudo apt install git

# Fedora
sudo dnf install git

# Arch
sudo pacman -S git

설치 확인

터미널에서 다음을 실행해 버전이 출력되면 설치가 완료된 것입니다.

git --version

초기 설정

커밋에 기록될 이름과 이메일을 한 번 설정합니다. 전역(--global) 설정이 일반적입니다.

git config --global user.name "홍길동"
git config --global user.email "you@example.com"

기본 편집기, 줄바꿈 처리 등은 필요할 때 추가로 설정합니다.

# Windows에서 줄바꿈 자동 변환 (권장)
git config --global core.autocrlf true

# macOS / Linux
git config --global core.autocrlf input

# 설정 목록 확인
git config --global --list

기본 사용법

새 프로젝트를 시작하거나, 이미 있는 폴더를 Git으로 관리하는 두 가지 경로가 있습니다.

새 저장소 만들기

mkdir my-project && cd my-project
git init
# 파일 작성 후
git add .
git commit -m "첫 커밋"

기존 원격 저장소 복제

git clone https://github.com/username/repo.git
cd repo

자주 쓰는 명령어

명령어 설명
git status 변경·스테이징 상태 확인
git add <파일> 다음 커밋에 포함할 변경 스테이징
git commit -m "메시지" 스테이징된 내용을 커밋
git log 커밋 이력 보기 (--oneline으로 요약)
git diff 작업 트리와 스테이징/커밋 간 차이 보기
git restore <파일> 미커밋 변경 되돌리기 (구버전: checkout)

일반적인 작업 흐름

  1. 파일을 수정한다.
  2. git status로 변경을 확인한다.
  3. git add로 커밋할 내용을 고른다.
  4. git commit으로 로컬에 기록한다.
  5. 원격이 있다면 git push로 업로드한다.
git status
git add src/app.js
git commit -m "로그인 폼 유효성 검사 추가"
git push

커밋 메시지는 무엇을, 왜 바꿨는지 짧고 명확하게 쓰는 것이 좋습니다. 예: fix: 빈 이메일 제출 시 400 반환

브랜치와 병합

기능 단위로 브랜치를 만들면 main(또는 master)을 안정적으로 유지할 수 있습니다.

git branch feature/login      # 브랜치 생성
git switch feature/login      # 브랜치로 이동 (구버전: checkout)
# 작업 후 커밋
git switch main
git merge feature/login       # main에 병합
git branch -d feature/login   # 병합된 브랜치 삭제

같은 줄을 두 사람이 수정하면 충돌(conflict)이 날 수 있습니다. 충돌 표시를 해결한 뒤 git add → git commit으로 병합을 마칩니다.

원격 저장소

GitHub 등과 연동할 때 자주 쓰는 명령입니다.

# 원격 추가 (clone 시에는 자동)
git remote add origin https://github.com/username/repo.git

# 원격 이름·URL 확인
git remote -v

# 가져오기 (병합 없이 이력만)
git fetch origin

# 가져와서 현재 브랜치에 병합
git pull origin main

# 로컬 커밋 업로드
git push -u origin main

-u(upstream)는 이후 git push, git pull만으로 같은 원격·브랜치를 사용하게 해 줍니다.

실무 팁

  • .gitignore — 빌드 산출물, node_modules, 비밀키 등은 커밋하지 않도록 목록을 둡니다.
  • 작은 커밋 — 논리 단위로 나누면 리뷰와 되돌리기가 쉬워집니다.
  • push 전 pull — 원격 변경을 먼저 받아 충돌을 줄입니다.
  • 도움말 — git help commit처럼 명령별 문서를 볼 수 있습니다.
